# MLX Backend for PE-Core-G

Native MLX port of `vit_pe_core_gigantic_patch14_448` (50-block EVA-style ViT, 1.88B params). Default backend for PE-G in `extract_features.py`; PyTorch fp16 retained as fallback via `--pecore-g-backend pytorch`.

## Files

- `model.py` — MLX model. Pre-norm blocks, fused QKV, plain GELU MLP (not SwiGLU), AttentionPoolLatent with 1 latent query, NHWC patch embed.
- `rope.py` — 2D-axial RoPE buffer matching timm's `RotaryEmbeddingCat` exactly (interleaved pair rotation, `grid_indexing='xy'`, `grid_offset=0.0`, theta=10000). Run as a script to verify the buffer matches timm's.
- `convert.py` — PyTorch state_dict → MLX safetensors. Strips `visual.trunk.` prefix, transposes patch_embed Conv2d weight `(O,I,kH,kW) → (O,kH,kW,I)` for MLX's NHWC. Auto-runs on first PE-G extraction; ~5 min, writes ~7.5GB to `~/.cache/mlx-pe-core-bigg.safetensors`. Logs to stderr — `cluster.ts` parses `extract_features.py` stdout as JSON, so anything called from inside the script must keep stderr/stdout split clean.
- `validate.py` — end-to-end cos similarity against open_clip with stage-by-stage drilldown on failure.

## Configuration

- `--pecore-g-backend mlx|pytorch` (default `mlx`)
- `--pecore-g-mlx-dtype float32|float16` (default `float32`)

## Validated equivalence

| Mode | vs open_clip | Notes |
|---|---|---|
| MLX fp32 | cos = 1.000000 | Bit-identical to PyTorch fp32 (post-L2-norm) |
| MLX fp16 | cos > 0.99998 | Drift only from MLX vs PyTorch fp16 op ordering |

Existing caches generated by PyTorch fp32 stay valid when switching to MLX fp32 — no re-extraction needed.

## Performance findings (100-image benchmark)

| Config | Wall time | vs original |
|---|---|---|
| PyTorch fp32 (original) | 85.0s | 1.00× |
| PyTorch fp16 | 75.2s | 1.13× |
| MLX fp32 | 66.7s | 1.27× |
| MLX fp16 | 64.2s | 1.33× |

**Lessons:**
- Framework choice dominates over precision on Apple Silicon. MLX fp32 alone beats PyTorch fp16.
- Apple GPU is compute-bound, not bandwidth-bound, at PE-G's scale — no NVIDIA-style fp16 throughput multiplier to chase. fp16 buys only ~4% in MLX.
- `mx.compile` is a wash on dense transformer inference; eager MLX is already well-fused for matmul.
- Larger batches don't help — GPU saturates at batch 8 for PE-G.

## PE-G architecture quirks (port traps)

- No CLS token, no register tokens, no LayerScale, no QK-norm (G14 specifically; the L/B variants differ).
- Both learned absolute `pos_embed` AND 2D-axial RoPE are active simultaneously — easy to drop one by accident.
- 2D-axial RoPE: head_dim=96 split into 48 (x-axis) + 48 (y-axis). Interleaved pair rotation (`half=False`), `grid_indexing='xy'`, `grid_offset=0.0` for G14 (note: L/B variants use `grid_offset=1.0`).
- RoPE applied only to Q/K, never V, and never inside `attn_pool`.
- `attn_pool` head_dim is 192 (8 heads × 192 = 1536), different from the main blocks' 96. Don't share head_dim constants.
- MLP hidden = 8960 exact (not derived from a clean ratio).
- patch_embed Conv2d has `bias=False` (because `use_pre_transformer_norm=True`).
- GELU is exact (`approximate='none'`), not the tanh approximation.
- Image preprocessing uses OpenAI CLIP mean/std (not Meta's 0.5/0.5 from the upstream repo) — open_clip's preprocess is what gets cloned.
